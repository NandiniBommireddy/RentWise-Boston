Serious

Serious Scrollable regions are not keyboard-operable WCAG 2.1.1 Keyboard

The locations list, citations list, and the answer card are internally scrollable (overflow-y: auto) to keep the one-page layout, but none are focusable. A keyboard-only user cannot scroll them at all — with 6+ locations or 12 citations, everything below the fold of each panel is unreachable without a mouse.

SourcesPanel.svelte (.locations, .citations) · App.svelte (.answer-row)

Fix: add tabindex="0" plus an accessible name to each scrollable container, e.g. <ul class="locations" tabindex="0" aria-label="Locations referenced">. Arrow keys then scroll them natively.

Serious Results are never announced to screen readers WCAG 4.1.3 Status Messages

The loading state announces itself (role="status" + aria-live="polite" — good), but when the answer arrives that region is removed and the results render silently. A screen-reader user hears "Searching RentSmart records…" and then nothing; they must wander the page to discover the answer appeared. Answers take 5–20s, so this is the app's core interaction.

App.svelte — the {#if} branch swap between loading and done states

Fix: keep one persistent aria-live="polite" region that gets a short message on completion ("Answer ready — N locations found"), or put aria-live="polite" on the answer section itself. Moving focus to the answer heading is an alternative pattern.

Moderate

Moderate Map content has no non-visual or keyboard equivalent surfaced as such WCAG 1.1.1 · 2.1.1

The Mapbox GL canvas is invisible to assistive tech: markers are not focusable, popups open on click only, and the canvas has no text alternative. The saving grace is that the locations list presents the same data in text — but nothing tells an AT user that the list is the map's equivalent.

MapPanel.svelte · SourcesPanel.svelte

Fix: add role="img" and a summary label to the map container (aria-label="Map of N reported locations; details in the locations list"). Keeping list/map parity (already true today) is the main line of defense — preserve it as the app grows.

Moderate Animations ignore prefers-reduced-motion WCAG 2.3.3 Animation from Interactions

The loading spinner spins unconditionally, and the map performs 1.2-second flyTo/fitBounds camera animations on every result — large full-viewport motion for vestibular-sensitive users.

App.svelte (@keyframes spin) · MapPanel.svelte (duration: 1200)

Fix: wrap the spinner animation in @media (prefers-reduced-motion: no-preference) (falling back to a static indicator), and in MapPanel set duration: 0 when matchMedia('(prefers-reduced-motion: reduce)').matches.

Moderate Citation links open new tabs without warning, and details hide in title WCAG 3.2.2 (advisory) · 1.1.1

Every citation link uses target="_blank" with no indication it leaves the app — disorienting for screen-reader and cognitive-load-sensitive users. The record detail is only in the title attribute, which touch users can never see and screen readers expose inconsistently.

SourcesPanel.svelte:39

Fix: append visually-hidden text <span class="sr-only">(opens data.boston.gov in a new tab)</span> (or a small ↗ icon with aria-hidden plus the sr-only text), and move the essential parts of detail into visible text or aria-label.

Moderate Placeholder is the only visible label, in default (low-contrast) gray WCAG 1.4.3 · 3.3.2

The query input has a proper aria-label (good) but no visible label; the unstyled placeholder (~#a9a9a9 in Chrome, ≈2.6:1 on white) is below the 4.5:1 threshold and vanishes on input, leaving sighted users without a prompt.

QueryBar.svelte:34

Fix: style ::placeholder { color: var(--text-muted); opacity: 1 } (4.8:1). The suggestion chips partly compensate for the missing visible label; a small visible label above the field would fully resolve 3.3.2.

Minor

Minor Heading hierarchy skips from h1 to h3 WCAG 1.3.1 (best practice)

"Locations referenced" and "Grounded in N records" are <h3> with no <h2> anywhere, so heading-based navigation presents a gap. The answer card has no heading at all.

SourcesPanel.svelte

Fix: promote the panel headings to h2 (they are visually styled already), and give the answer section a visually-hidden h2 ("Answer") — this also gives the focus-management fix above a target.

Minor Dataset tag text is 10.9px Readability

The RentSmart / Short-Term pills render at 0.68rem ≈ 10.9px. Contrast passes (4.8:1) but the size is below comfortable minimums for low-vision users.

SourcesPanel.svelte (.dataset-tag)

Fix: bump to 0.75rem (12px); the pill layout absorbs it.

Minor No skip link WCAG 2.4.1 Bypass Blocks

Keyboard users tab through the input and four suggestion chips before reaching results on every visit. Landmarks (header/main/footer) exist, which satisfies 2.4.1 minimally, but a "skip to results" link once results exist would help heavy keyboard users.

Fix: optional; lowest priority. The focus-management fix under "Serious" largely obviates it.
